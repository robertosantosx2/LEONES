# FreeToken / MoE benchmark contract

## Purpose

This is the LEONES reproducibility contract for the FreeToken edge-MoE candidate. It does **not** import the paper's performance numbers into LEONES measurements. The paper is an external prior; every LEONES result must be generated by the canonical runtime + benchmark + evidence pipeline.

Primary source: `docs/sources/FREETOKEN.md`.

## Candidate gate

A FreeToken plan is eligible only when all of the following are known:

- model is MoE;
- workload has agentic affinity when the benchmark is agentic;
- GPU VRAM and host RAM are profiled;
- host-memory bandwidth is measured;
- pinned PCIe host→device bandwidth is measured;
- CPU-side MoE bandwidth is measured;
- model total parameters and active parameters are identified;
- quantization/weight size is pinned;
- runtime command is supplied by trusted configuration.

A model fitting comfortably in VRAM is not a reason to choose FreeToken.

## Comparators

Use the same model/checkpoint, quantization, prompt/task set, context policy and measurement protocol when a comparator has an executable route:

- llama.cpp;
- KTransformers;
- other runtime explicitly declared compatible by the benchmark manifest.

If a comparator cannot execute the exact cell, record `not_comparable` with the reason. Do not substitute another model or silently change quantization.

## Agentic workload set

The target suite should cover:

1. AIME/reasoning workload;
2. SWE/OpenCode coding agent with tools;
3. Claude-compatible multi-turn coding agent;
4. OpenClaw email/calendar task.

The task revision, tool policy, sandbox, model revision and prompt set are part of the run identity.

## Required evidence

Record, when supported by the runtime:

- TTFT p50/p95/p99;
- prefill throughput;
- decode tok/s / TPOT;
- peak GPU VRAM;
- host RAM;
- measured host-memory bandwidth;
- measured PCIe H→D bandwidth;
- CPU MoE bandwidth;
- expert cache hit/miss;
- CPU/GPU expert execution split;
- startup/warm-up time;
- context-growth behavior;
- multi-turn behavior;
- tool-call latency;
- energy when available;
- task outcome and grader result.

## Evidence status

- `reported`: copied from an external publication or report;
- `estimated`: produced by a model/runtime estimator;
- `measured`: captured from an actual LEONES execution;
- `verified`: independently checked against the retained primary evidence.

The runner must never promote `reported` or `estimated` to `measured`.

## Reproduction boundary

The published FreeToken paper values, including its RTX 4060 Laptop and RTX PRO 6000 reference results, remain **external evidence** until the corresponding LEONES cells are actually executed and retained with their raw trace, normalized result and grader/evidence record.
