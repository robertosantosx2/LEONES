## Principle

LEONES should promote itself through real project activity rather than generic advertising. A useful event should become reusable content:

`discovery → analysis → test → result → GitHub → web → social post`

## Recommended cadence

### Daily

- Discover new local-AI, agentic, model, backend and harness projects.
- Detect licence changes and candidate Copyleft projects.
- Record candidates for later evaluation.

### Weekly

Publish a LEONES Weekly summary containing new discoveries, evaluated stack components, notable manada_leones hardware results and one useful technical finding.

### Monthly

Publish a broader ecosystem report with trends, new recommendations, benchmark evolution and changes to the recommended stacks.

## X / @manadaleonesia

Posts should be evidence-led. Prefer:

- real benchmark results;
- new project discoveries;
- hardware comparisons;
- useful stack changes;
- weekly summaries;
- links to reproducible GitHub results.

Avoid automated high-volume posting or engagement bait.

## GitHub community

Use Issues for actionable discovery and work items. Use Discussions for questions, hardware reports, stack discussions and community knowledge. Use Releases for meaningful milestones.

## Hardware Wall

The long-term goal is a public comparison of anonymised real-world hardware and software configurations submitted through manada_leones. Every report should exclude personal information, credentials, identifiers and private filesystem information.

## Automation target

GitHub Actions should eventually automate:

1. daily discovery;
2. weekly report generation;
3. monthly ecosystem report;
4. regeneration of result statistics and charts;
5. preparation of social content from verified project activity.

Social publication itself should remain subject to an explicit, auditable policy and should never publish private data.
