<h1>Motores de inferencia local para ODS</h1>
<p class="lead">Análisis técnico comparativo orientado a <b>ODS</b>. Incluye el mapa completo de candidatos de prospección: generalistas, MoE/memoria/streaming, segunda línea (P2/P3) e integraciones experimentales. La unidad de decisión es <i>modelo + engine + configuración + hardware + objetivo + evidencia MEASURED</i> (<b>Inference Configuration Discovery</b>).</p>
<div class="meta">
<span class="pill">Actualizado: 2026-10-06</span>

<h2>Resumen ejecutivo — candidatos prioritarios</h2>
<div class="grid">
<div class="card" data-tier="general"><h3>llama.cpp / cafe-llama.cpp</h3><div class="score">★★★★★</div>
<p><b>Núcleo actual ODS y baseline universal.</b> GGUF, cuantización, CPU/GPU híbrida, offload MoE, KV low-bit, MTP. cafe añade rutas Qwen3.8-Flash-Next (PLE, host MoE, expert cache).</p>
<span class="tag">Generalista</span><span class="tag">Baseline ODS</span><span class="tag">ggml</span></div>

<div class="card" data-tier="general"><h3>vLLM · SGLang</h3><div class="score">★★★★☆</div>
<p><b>Serving de alto throughput en CUDA.</b> vLLM: continuous batching, paged KV, ecosistema maduro. SGLang: scheduling y runtime optimizado. Candidatos cuando ODS actúa como servidor multi-usuario/batch, no solo desktop single-user.</p>
<span class="tag">High-throughput</span><span class="tag">CUDA</span><span class="tag">Serving</span></div>

<div class="card" data-tier="general"><h3>LocalAI · llama-cpp-studio</h3><div class="score">★★★☆☆</div>
<p><b>Referencias de abstracción y control-plane.</b> LocalAI: multi-backend. llama-cpp-studio: orquestación multi-runtime. Útiles como patrones arquitectónicos para el selector de ODS, no necesariamente como únicos engines de producción.</p>
<span class="tag">Abstraction</span><span class="tag">Control-plane</span></div>

<div class="card" data-tier="moe"><h3>Strata</h3><div class="score">★★★★★</div>
<p><b>Especialista MoE gigante en PC de consumo.</b> Expert cache adaptativo, KV streaming, CPU+GPU en paralelo, MTP. Objetivo principal: Qwen3.8-Flash-Next.</p>
<span class="tag">MoE consumo</span><span class="tag">Expert cache</span><span class="tag">CUDA/HIP</span></div>

<div class="card" data-tier="moe"><h3>MoE-Infinity · ramvamp · WARP · FrankenMoE</h3><div class="score">★★★★☆</div>
<p><b>Eje “hacer caber MoE”.</b> Offload host/SSD (MoE-Infinity), streaming CPU/NVMe (ramvamp), paging NVMe (WARP), tiers NVMe→RAM→VRAM (FrankenMoE-CUDA).</p>
<span class="tag">Offload</span><span class="tag">NVMe</span><span class="tag">MoE</span></div>

<div class="card" data-tier="moe"><h3>Edge0 · BigMoeLLM · moe-stream</h3><div class="score">★★★★☆</div>
<p><b>SSD/flash en el camino crítico.</b> Demand-paged experts, routing prediction, modos resident/hybrid/streaming. Edge y “modelo > RAM”.</p>
<span class="tag">SSD streaming</span><span class="tag">Edge</span></div>

<div class="card" data-tier="moe"><h3>FATE · HybriMoE · HOBBIT</h3><div class="score">★★★☆☆</div>
<p><b>Capacidades componibles</b> del Capability Registry: predicción de expertos, scheduling CPU/GPU, cache multidimensional y precisión adaptativa. No solo backends monolíticos.</p>
<span class="tag">Prediction</span><span class="tag">Scheduling</span><span class="tag">Adaptive cache</span></div>

<div class="card" data-tier="experimental"><h3>TensorFold</h3><div class="score">★★★★☆</div>
<p><b>Acelerador de decode</b> (draft + verify). Fuerte en Apple Silicon (MLX) y CUDA. Entra en el espacio de búsqueda cuando el modelo cabe y el objetivo es maximizar tok/s.</p>
<span class="tag">Speculative</span><span class="tag">MLX/CUDA</span></div>

<div class="card" data-tier="experimental"><h3>AirLLM · Kimi K3 · LaptopLLM · Companion Hub</h3><div class="score">★★★☆☆</div>
<p><b>Experimentales.</b> Layer/expert streaming (AirLLM, Kimi K3, LaptopLLM) y referencia de orquestación de aplicación local (Companion Hub). Radar de prospección; validar con evidencia MEASURED antes de producción.</p>
<span class="tag">Experimental</span><span class="tag">Streaming</span></div>
</div>
