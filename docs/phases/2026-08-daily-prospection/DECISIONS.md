# Decisiones — Prospección diaria

## D1 — Prospección diaria

La prospección se ejecuta diariamente porque el ecosistema cambia con demasiada rapidez para depender de una actualización manual.

## D2 — OSI como puerta de entrada

Se utiliza el estado OSI como filtro de entrada al conjunto principal. Esto no equivale a afirmar que el proyecto sea recomendable.

## D3 — Copyleft prioritario

GPL/AGPL/LGPL reciben tratamiento prioritario, pero no se confunden con aprobación técnica.

## D4 — Licencia declarada ≠ licencia verificada

El SPDX declarado por GitHub sirve para descubrimiento. No sustituye la revisión del repositorio, ni determina por sí solo las condiciones de los pesos de un modelo.

## D5 — Descubrimiento ≠ evidencia

El prospector descubre. La validación requiere una etapa posterior con evidencia apropiada.

## D6 — Recomendación posterior

Un hallazgo solo puede alimentar recomendaciones después de revisar relevancia, compatibilidad, dependencias, reproducibilidad, seguridad y evidencia.
