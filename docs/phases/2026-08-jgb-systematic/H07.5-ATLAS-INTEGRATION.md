# H07.5 — Integración JGB con Atlas y Router

## Estado

**🟢 COMPLETADA como contrato de integración.**

H07 completo sigue **🟡** hasta la validación final de datos JGB verificados.

## Objetivo

Hacer que la clasificación JGB pueda viajar desde la capa de evidencia hasta Atlas y el Router sin sustituir otras propiedades del modelo.

## Regla fundamental

JGB es una dimensión de conocimiento independiente. No reemplaza:

- CABE/RULA;
- benchmarks;
- rendimiento medido;
- calidad;
- `fit_score`;
- self-hostability;
- licencia como campo independiente.

El README de Atlas ya establece que las capas de conocimiento, evidencia y recomendación deben permanecer separadas y que el Router solo puede usar hechos cuya evidencia sea adecuada. fileciteturn123file0L2-L2

## Forma recomendada del dato

El registro Atlas debe conservar, cuando exista evidencia suficiente:

```json
{
  "jgb": {
    "class": 4,
    "label": "Open source model",
    "access": "verified",
    "model_control": "verified",
    "data_control": "verified",
    "autonomy": "verified",
    "trust": "provisional",
    "confidence": "high",
    "evidence": [
      {
        "source_url": "...",
        "checked_at": "..."
      }
    ]
  }
}
```

El ejemplo es estructural: los valores reales solo se rellenan cuando existe evidencia para ese modelo.

## Reglas de promoción

1. `unknown` no se convierte en `verified`.
2. `provisional` no se presenta como hecho confirmado.
3. Una clase JGB no se calcula desde `fit_score`.
4. Un benchmark no eleva la clase JGB.
5. La capacidad de ejecución local no eleva la clase JGB por sí sola.
6. Las evidencias se conservan junto con la clasificación.
7. Si falta una condición necesaria para una clase, no se promociona esa clase.

## Router

El Router puede consultar JGB para responder preguntas como "¿qué grado de libertad tiene este modelo?", pero debe respetar el estado de evidencia.

```text
Router pregunta por JGB
        ↓
¿Atlas tiene JGB adecuado?
   ├── SÍ → devolver clase + evidencia/estado
   └── NO → unknown
```

Nunca debe inferir una clase JGB a partir de otros campos del Atlas.

## Compatibilidad con Atlas

El Atlas ya separa modelos, software, hardware, experimentos, evidencia y recomendaciones, y exige que el Router no invente cuando un hecho adecuado no está disponible. fileciteturn123file0L2-L2

Por ello la integración JGB se trata como **atributo de conocimiento con procedencia**, no como un score global.

## Privacidad

La evidencia JGB debe respetar las mismas reglas de privacidad del Atlas: no introducir identidades de operadores, hostnames, números de serie, UUID, MAC/IP, localización exacta, credenciales o rutas privadas. fileciteturn123file0L2-L2
