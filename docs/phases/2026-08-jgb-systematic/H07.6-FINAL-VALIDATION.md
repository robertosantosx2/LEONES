
## Lista de comprobación

- [x] JGB se trata como conocimiento independiente.
- [x] Las dimensiones Access, Model control, Data control, Autonomy y Trust permanecen separadas.
- [x] `verified`, `provisional`, `unknown` y `disputed` se conservan como estados distintos.
- [x] La ausencia de evidencia no se convierte en una afirmación positiva.
- [x] JGB no se deduce de benchmarks.
- [x] JGB no se deduce de rendimiento.
- [x] JGB no se deduce de precio.
- [x] JGB no se deduce de self-hostability.
- [x] JGB no sustituye CABE/RULA.
- [x] JGB no sustituye `fit_score`.
- [x] Las fuentes y la fecha de comprobación forman parte de la trazabilidad.
- [x] El Router debe devolver `unknown` cuando no dispone de evidencia adecuada.
- [x] La integración no autoriza a inventar clases para los candidatos sin verificar.
- [x] La activación definitiva requiere validación humana restringida.
- [x] La validación humana se solicita mediante correo, no mediante formulario web.
- [x] Solo son válidas las seis respuestas exactas `OK LEONES CLASE0` a `OK LEONES CLASE5`.
- [x] Una respuesta distinta mantiene el registro en `pending_human_validation`.
- [x] La clase propuesta y la clase activada se conservan por separado.

## Primera prueba con modelos

Se han preparado tres casos iniciales para probar el circuito:

- Qwen3.5-9B
- Mistral-7B-v0.3
- Llama-3.1-8B

Los tres tienen **CLASE2 como propuesta de prueba**, no como clasificación activada. El dataset de pruebas está en `web/proyectos/atlas/openness/jgb_validation_test_cases.csv`.

La propuesta no se considera válida para publicación porque todavía quedan dimensiones con evidencia `provisional` o `unknown`. Esto es deliberado: el evaluador automático debe impedir la activación hasta que exista evidencia suficiente y se produzca la respuesta humana exacta.

## Resultado de la validación

El contrato de H07 está cerrado a nivel de infraestructura y proceso. El trabajo factual continúa modelo por modelo.

Por tanto, no se cambia H07 a `🟢 CERRADA` todavía.

## Qué queda realmente pendiente

La tarea pendiente ya no es diseñar el mecanismo, sino **obtener y registrar evidencia primaria real para los candidatos**, completar las dimensiones necesarias y obtener la activación humana correspondiente para las clases que vayan a publicarse.

Un candidato sin evidencia suficiente permanece `unknown` y no bloquea la calidad del resto del Atlas.

## Regla de no concurrencia

Cualquier workflow futuro que escriba en el catálogo o artefactos canónicos debe respetar la regla global de no concurrencia de LEONES. La validación JGB no crea una excepción a esa regla.

## Criterio de cierre global

H07 solo pasará a 🟢 cuando las clasificaciones que se publiquen como activadas dispongan de evidencia suficiente y reproducible, la activación humana esté registrada y una auditoría confirme que no se han inferido desde propiedades ajenas al marco JGB.
