Horizon

AI-powered news radar: un radar personal que recopila noticias y actividad de múltiples fuentes, elimina duplicados, analiza y filtra contenidos, añade contexto y genera briefings diarios.

Ver proyecto en GitHubVolver a LEONES
¿QUÉ HACE?

Del ruido a una lectura priorizada

Según su documentación, Horizon puede vigilar Hacker News, RSS/Atom, Reddit, Telegram, Twitter/X, actividad y releases de GitHub y fuentes financieras mediante OpenBB. Después recopila, deduplica, analiza/filtra, enriquece y resume.

Función clave: convertir muchas fuentes heterogéneas en un briefing estructurado y configurable, manteniendo al usuario dentro del circuito de decisión.

Cómo funciona

Fuentes→Fetch→Deduplicate→AI analyse/filter→Enrich→Summarize→Deliver

Fuentes

Hacker News · RSS · Reddit · Telegram · Twitter/X · GitHub · OpenBB.

Salidas

GitHub Pages · email · webhooks · MCP · archivos locales.

Configuración

Permite ajustar fuentes, perfiles de procesamiento, modelos, idiomas y canales de entrega.

Instalación

git clone https://github.com/Thysrael/Horizon.git
cd Horizon
uv sync
uv run horizon

El proyecto también documenta instalación editable con pip y ejecución mediante Docker Compose.

Automatización

Horizon está orientado a ejecuciones recurrentes y puede publicar un sitio diario en GitHub Pages, enviar correo o enviar resultados a canales mediante webhooks. También expone herramientas mediante MCP.

🦁 Por qué interesa a LEONES

Potencial: Alto — candidato para evaluación.

Horizon encaja especialmente bien con el radar de prospección que estamos construyendo: ya implementa un ciclo de observación de fuentes, deduplicación, análisis, enriquecimiento y publicación. Puede ser útil como pieza para descubrir y mantener conocimiento sobre nuevos proyectos, modelos, releases y noticias del ecosistema.

También es interesante por su integración con MCP, GitHub Pages y múltiples canales de salida. Eso abre una posible vía para que LEONES no solo descubra piezas nuevas, sino que mantenga un flujo continuo de información sobre ellas.

Pero no se incorpora automáticamente a la pila: el radar lo clasifica como descubrimiento y candidato. Antes de recomendarlo hay que evaluar su funcionamiento real, coste, dependencias, calidad del filtrado, facilidad de ejecución local y encaje con el resto de la arquitectura LEONES.

Qué debemos comprobar

  • Consumo de CPU/RAM durante una ejecución completa.
  • Qué modelos y APIs pueden utilizarse localmente.
  • Calidad de deduplicación y filtrado.
  • Calidad y coste del enriquecimiento web.
  • Utilidad real de MCP para integrar Horizon con el ecosistema agentivo.
  • Posibilidad de usarlo como componente del radar diario de LEONES.
