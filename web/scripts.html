LEONES · Scripts locales

Herramientas autónomas para que una persona pueda probar su LLM en su propio equipo sin instalar la infraestructura de LEONES.

Criterio

La web explica; el script ejecuta

Los scripts locales no son una copia de la infraestructura. Son herramientas pequeñas, documentadas y con una responsabilidad concreta que pueden ejecutarse de manera independiente.

Frontera: el usuario descarga los scripts que necesita, no la web ni toda la infraestructura de LEONES.

Cadena de trabajo

Hardware → Modelo → Runtime → Inferencia → Evaluación → Resultado

LLM Smoke Test

Es la primera herramienta local cerrada según este criterio. Comprueba que un runtime puede ejecutar un modelo local y devuelve un resultado estructurado.

Contrato

RESULT_SCHEMA v0.1 define una estructura común para los resultados.

llama.cpp

Primer adaptador ejecutable. Está pensado para modelos locales compatibles, especialmente GGUF.

Ollama

Runtime de primera prioridad para ofrecer una entrada sencilla a usuarios de escritorio.

Próximas capas

Transformers y vLLM están en la siguiente prioridad; MLX queda reservado para una fase específica de Apple Silicon.

Cómo se mide

El resultado común puede contener TTFT, tiempo de generación, tiempo total, tokens de entrada y salida, tokens por segundo y memoria cuando pueda medirse de forma fiable.

Regla de integridad: una métrica desconocida o no medible es null. Nunca se utiliza 0 para ocultar que una medición no existe.

Aislamiento

No necesita LEONES

El paquete local no importa Atlas, agentes, workflows ni componentes internos de la infraestructura.

No descarga modelos silenciosamente

El usuario controla qué modelo utiliza y dónde está almacenado.

No necesita credenciales

Las pruebas locales están diseñadas para funcionar sin autenticación contra servicios de LEONES.

Salida auditable

Los resultados son JSON y pueden validarse antes de incorporarlos a otros procesos.

Para quien quiera probarlo

El paquete vive en scripts/local/llm-smoke-test y contiene su propia documentación, esquema, validación y pruebas. La entrada de pruebas es run_tests.py; el resultado puede comprobarse con validate_result.py.

La web no necesita conocer la implementación interna para explicar el producto. Esa separación es deliberada y será mantenida en futuras versiones.
