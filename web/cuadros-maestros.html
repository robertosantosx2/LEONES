Cuadros maestros · hardware → LLM

Tres matrices por clase de CPU (Intel + Ryzen equivalente). Columnas = RAM del sistema. Filas = GPU de consumo ordenadas por potencia. Celda = mejor modelo open-weight viable según ranking de Artificial Analysis (Intelligence Index), acotado por VRAM/RAM realistas en cuantización práctica (Q3–Q5 / MoE).

Contrato de lectura

ESTIMATED ≠ MEASURED. Las celdas son una clasificación de encaje: el LLM open-weight con mejor señal AA que cabe de forma usable en ese presupuesto de memoria. No es una medición LEONES de tok/s ni de calidad agentica en ese hardware.
Reglas de encaje: (1) Limita primero la VRAM de la GPU; la RAM del sistema solo permite offload/CPU-only y no multiplica la VRAM. (2) 2–4 GB de RAM de sistema = no usable para LLM modernos (salvo experimentación). (3) Solo modelos open-weight (ejecutables en local). (4) Índice AA = Intelligence Index v4.x, open weights, referencia ~sept 2026. (5) Cuantización típica Q4_K / Q3_K_XL; contexto corto–medio (~4–8K) salvo que se indique.

Notas metodológicas

  • Por qué no aparecen Kimi K3 / GLM-5.3 completos: son MoE de cientos de miles de millones de parámetros; en PC de consumo solo entran en modo parcial/offload muy degradado, no como “el que más puntúa y corre bien”.
  • CPU equivalent: i5≈R5 (6–8–10c), i7≈R7 (8–12c), i9≈R9 (12–16c+). El salto real está en núcleos, IMC y canales de memoria para offload.
  • 2 / 4 GB RAM: marcados no viables: el SO + runtime ya consumen ese margen.
  • Actualización: re-rankear cuando Artificial Analysis mueva el top open-weight o salgan GGUF medidos nuevos (p. ej. vía MSA Run local).
  • LEONES: estas celdas alimentan candidatos; el benchmark propio decide measured.
