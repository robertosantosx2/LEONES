Arquitectura

La pila no es solo el modelo

LEONES trata la ejecución local como una cadena de capas. Cada una puede cambiar sin obligar a sustituir todo el sistema. 

HARDWARE
   ↓
SISTEMA OPERATIVO
   ↓

   ↓

   ↓

   ↓

   ↓

Qué aporta cada capa

Hardware

CPU, GPU, RAM, VRAM y almacenamiento determinan qué modelos y runtimes son realmente viables.

Sistema y runtime

El sistema operativo, drivers y runtime gestionan la ejecución y el acceso efectivo a los recursos disponibles.

Inferencia

Backend, formato, modelo y cuantización determinan cómo se convierten los recursos del equipo en tokens y latencia.

Capa agentic

Harness, herramientas, skills y conocimiento convierten la inferencia en capacidad para completar objetivos.

Evaluación

LOTB y las pruebas reproducibles permiten separar percepción, afirmaciones y evidencia medible.

Resultado y UX

El resultado final importa por lo que permite hacer al usuario, no por el número de tokens producido por segundo de forma aislada.

Web e infraestructura no son la misma capa

La web de LEONES documenta, explica y presenta el ecosistema. La infraestructura mantiene datos, procesos y automatización. Los scripts locales son una frontera distinta: deben poder copiarse y ejecutarse sin instalar toda esa infraestructura.

Decisión: la web no se diseña como un paquete que el usuario tenga que descargar. Lo descargable son las herramientas locales necesarias para realizar pruebas en su propio equipo.

Objetivo de Router

Router debe encontrar la combinación que satisfaga una necesidad con el hardware disponible, utilizando evidencia real y declarando incertidumbre cuando falte información.

Necesidad → Hardware → Modelo → Runtime → Agentic stack → Evaluación
