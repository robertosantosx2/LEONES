## Regla de identidad

Cada nombre se trata como una identidad exacta. Los calificadores `máx.`, `Pro`, `A95B`, `A55B` y `high` no se eliminan ni se interpretan como equivalentes a otra variante sin evidencia primaria.

Antes de evaluar JGB debe existir una identidad trazable para el artefacto concreto: proveedor/organización, repositorio o página canónica, variante, licencia y fuente primaria.

## Evaluación JGB

Para cada modelo se documentarán por separado:

- `access`
- `model_control`
- `data_control`
- `autonomy`
- `trust`

No se asignará una clase global cuando falte evidencia suficiente. La ausencia se conserva como `unknown`; una afirmación provisional no se promociona automáticamente.

## Fuentes de investigación inicial

### Kimi K3

Fuente primaria: repositorio oficial de Moonshot AI, `MoonshotAI/Kimi-K3`. Describe Kimi K3 como open-weight, nativamente multimodal y agentic, con 2.8T parámetros y 1M de contexto. urlRepositorio oficial Kimi K3https://github.com/MoonshotAI/Kimi-K3

### Qwen3.8 2.4T A95B

Identificador de pesos localizado: `Qwen/Qwen3.8-2.4T-A95B` en Hugging Face. El registro de H07 mantiene pendiente la lectura del model card y licencia primaria antes de convertirlo en evidencia JGB cerrada. urlQwen3.8-2.4T-A95B en Hugging Facehttps://huggingface.co/Qwen/Qwen3.8-2.4T-A95B

### DeepSeek V4 Pro 0813

El lanzamiento GA de V4 Pro 0813 está documentado públicamente; la variante admite niveles de esfuerzo `low`, `high` y `max`. Para H07 se debe separar el hecho de que la API exponga el modelo de la cuestión de acceso a pesos, licencia y control del artefacto. citeturn2news30turn2reddit31

### MiniMax M3

La página oficial de MiniMax identifica M3 como open-weight, con 1M de contexto y capacidades de despliegue local; anuncia que los pesos se publican para despliegue privado y fine-tuning. citeturn1search0turn1search1

La licencia comunitaria debe tratarse como evidencia separada: las condiciones comerciales no son equivalentes a una licencia OSI permisiva. citeturn1search2turn1search3

### GLM-5.2

El model card público de `zai-org/GLM-5.2` declara licencia MIT, pesos en Safetensors y uso local mediante Transformers. citeturn0search2

### Nemotron 3 Ultra 550B-A55B

NVIDIA documenta cuatro checkpoints y señala que publica también recetas de entrenamiento, datos y entornos RL. La documentación NIM identifica el checkpoint NVFP4 bajo OpenMDW-1.1. citeturn0search83turn0search1

### Muse Glimmer

Se ha localizado evidencia pública del modelo Muse Glimmer 30B y de sus variantes de ejecución local. Para H07 no se eleva esa evidencia comunitaria a evidencia primaria hasta disponer del artefacto/model card oficial correspondiente.

## Activación humana

La clasificación definitiva requiere una activación humana restringida. El formulario web deberá presentar el expediente y la clase propuesta, y la validación se solicitará mediante el canal definido por H07.

Las únicas respuestas de activación válidas serán exactamente:

```text
OK LEONES CLASE0
OK LEONES CLASE1
OK LEONES CLASE2
OK LEONES CLASE3
OK LEONES CLASE4
OK LEONES CLASE5
```

La clase propuesta y la clase autorizada se conservarán como campos independientes. Una respuesta `OK LEONES CLASEx` activa únicamente `CLASEx`.

## Criterio de cierre del lote

El lote no se considera terminado hasta que cada modelo tenga:

1. identidad exacta;
2. evidencia primaria trazable;
3. evaluación de las cinco dimensiones;
4. clase propuesta o `unknown` justificado;
5. solicitud de activación humana cuando proceda;
6. respuesta de activación registrada;
7. incorporación documentada en el Atlas solo cuando el gate correspondiente lo permita.
