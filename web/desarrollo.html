Desarrollo de LEONES

Normas básicas del proyecto

1. Código y documentación juntos

Todo cambio funcional relevante se documenta simultáneamente en el código, la documentación técnica y, cuando afecta al funcionamiento o arquitectura, en esta web. La documentación no se deja para el final.

2. Scripts pequeños

Scripts sencillos que hagan las menores cosas posibles y estén muy documentados.

Preferimos piezas pequeñas y componibles frente a un script monolítico.

hardware → model → infer → benchmark → report → publish

3. Autonomía

LEONES debe ejecutar modelos localmente sin depender de una aplicación de escritorio concreta. Los runtimes son adaptadores intercambiables.

4. Evidencia

Las mediciones deben conservar modelo, versión, cuantización, backend, hardware, configuración y estado de evidencia.

5. Cambios pequeños

Cada bloque debe poder probarse aisladamente. No se añade complejidad hasta que una necesidad real la justifique.
