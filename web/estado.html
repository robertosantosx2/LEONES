Pruebas físicas · septiembre

Lo que ya se ha demostrado

✓ Instalador mínimo

install.sh es ejecutable y prepara LEONES sin instalar automáticamente stacks ni modelos. LLMFit es dependencia dura y su ausencia produce un fallo explícito.

✓ Terminal

El lanzador restaura stty echo echonl antes y después del wizard. Las entradas del operador vuelven a ser visibles durante el flujo interactivo.

✓ Docker

RC2 detecta Docker directo y Docker mediante sudo, además de distinguir rootless y Podman. En la máquina de validación se observó Docker 29.1.3 + Compose v5.5.0 con acceso directo.

✓ ODS observado

La verificación física detectó ODS CLI v2.6.0 y la imagen ods-privacy-shield:latest. La presencia observada no se confunde con una medición de rendimiento.

✓ Cancelación

La cancelación del instalador externo devuelve código no cero y conserva el mensaje original. El wizard no la convierte en instalación exitosa.

✓ Desinstalación

--leones limpia el estado local sin borrar el checkout ni las evidencias históricas de artifacts/runtime-executions/.

Resolución modelo/runtime

La siguiente frontera de RC2

1 · Candidato

LLMFit entrega identidad, fit y rendimiento estimado. Todo permanece marcado como estimated.

2 · Resolución

LEONES determina qué runtime puede ejecutar realmente el artefacto seleccionado. Un ID HF/GGUF no se convierte silenciosamente en un nombre Ollama.

3 · Preparación

Preparar o instalar el artefacto requiere su propia autorización. La resolución no descarga ni ejecuta nada por sí misma.

4 · Verificación

Solo después de comprobar runtime y modelo disponibles se puede abrir la puerta de A01.

5 · Medición

La ejecución real produce métricas y evidencia nuevas. estimated nunca se transforma automáticamente en measured.

Runtime del host

Docker y Podman se detectan sin suposiciones

Docker

RC2 acepta Docker accesible directamente o mediante sudo. Rootful no es un error; rootless se registra como propiedad observada.

Podman

Puede estar presente como runtime del host, pero su presencia no se convierte por inferencia en una instalación ODS válida.

Compatibilidad

Runtime disponible → acceso funcional → Compose/interfaz compatible → señal específica de ODS. Cada estado tiene su propio gate.

Regla: que Docker o Podman funcionen demuestra capacidad del host; no demuestra que ODS esté instalado ni que un modelo concreto sea ejecutable.
