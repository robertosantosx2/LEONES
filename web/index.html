El proyecto

La idea en una pantalla

Estado: desarrollo

¿Qué intenta resolver?

LEONES estudia qué combinación de modelos, backends, harnesses y herramientas permite ejecutar IA agentic Libre/Open en hardware de consumo, priorizando Copyleft.

Idea central: un agente no existe para producir tokens; existe para completar objetivos.

Buddy

Conocimiento controlado, independiente de la máquina

Objetivo→Buddy
conocimiento + contexto→Harness / agente→Modelo→Resultado

¿Cómo se usa?

Buddy actúa como capa de conocimiento y contexto controlados: qué sabe el agente, qué documentos puede utilizar, qué información conserva y cómo recuperarla durante una tarea.

¿Por qué importa?

Separamos lo que el sistema sabe de la pieza que genera los tokens. Así podemos cambiar modelo, backend, hardware o harness sin reconstruir el conocimiento.

El conocimiento sobrevive al cambio de pila

Hardware y software evolucionan sin perder el trabajo acumulado

Instalación

De cero a una primera ejecución

1 · Clonar

git clone https://github.com/robertosantosx2/LEONES.git
cd LEONES

2 · Diagnóstico

python3 scripts/leones.py hardware

3 · GitHub

gh auth login

Solo es necesaria para publicar. Nunca guardes credenciales en un informe.

Ejecuciones

Cada script hace una tarea concreta

01

Hardware

python3 scripts/leones.py hardware
02

Modelo

python3 scripts/leones.py model modelo.gguf
03

Inferencia

python3 scripts/leones.py infer --url http://127.0.0.1:8080/v1/chat/completions --model local-model
04

LOTB

python3 scripts/leones.py lotb --endpoint http://127.0.0.1:8080

Diseño: hardware → model → infer → LOTB → report → publish → stats. El orquestador llama a piezas pequeñas; no sustituye su lógica.

Qué NO se publica

Nombres, emails, usuarios, hostnames identificables, seriales, UUID, MAC/IP, ubicación, rutas personales, credenciales o tokens.

Estados: reported → reproducible → verified. Un resultado publicado no se convierte automáticamente en verificado.
