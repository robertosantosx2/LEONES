Visión

IA local útil, no solo modelos ejecutándose

LEONES estudia la combinación de hardware, sistema operativo, runtime, backend, modelo, harness, skills y conocimiento necesaria para completar objetivos agentic localmente.

Un agente no existe para producir tokens; existe para completar objetivos.

Cómo se organiza el proyecto

Atlas

Base estructurada de modelos, familias, organizaciones, benchmarks, hardware y evidencia. Conserva conocimiento consultable.

Router

Capa de decisión que relaciona necesidad, hardware, modelo y runtime para encontrar una combinación viable.

Evaluación

Metodologías y pruebas que distinguen una afirmación de una medición reproducible.

Manada

Capa para agregar mediciones voluntarias y convertir experiencia real en nueva evidencia.

Scripts locales

La herramienta se separa de la infraestructura

Los scripts locales son herramientas pequeñas y autónomas que el usuario puede ejecutar en su propio equipo para probar su LLM con su hardware y su runtime.

Principio arquitectónico: la web es el escaparate; los scripts son herramientas locales autónomas.
Web LEONES→Documentación≠Scripts locales→LLM + runtime del usuario

LLM Smoke Test y ejecución real

Los smoke tests comprueban el contrato mínimo. RC1 añade la capa efectiva: selección autorizada, ejecución real, benchmark A01, grader y evidencia medida.

Contrato común

Los esquemas definen la estructura de resultados para que los adaptadores puedan compararse sin cambiar el significado de las métricas.

Runtimes

La ejecución real puede usar runtimes soportados por el registro; RC1 está validado con Ollama.

Medición honesta

Lo desconocido permanece como null; una estimación nunca se promociona a medición.

Aislamiento

No se requieren credenciales externas para la prueba local de referencia y los resultados no se envían a LEONES por defecto.

Para empezar

Qué debe decidir primero un usuario

1 · Hardware real

Importan memoria disponible, ancho de banda, interconexión y margen para modelo y contexto.

2 · Carga real

Define contexto, longitud de respuesta, concurrencia y si necesitas chat, coding, RAG, herramientas o agentes.

3 · Modelo + formato

La cuantización y la plantilla de chat forman parte del paquete del modelo y del runtime.

4 · Medir

Compara con tareas representativas y conserva la evidencia de cada ejecución.

Regla LEONES: elegir el modelo más pequeño que gane tu carga de trabajo real en tu hardware, no el modelo con la cifra de parámetros más grande.
