Cómo lee LEONES este estudio

La lista no es un ranking. Separa runtimes, servidores, stacks, aplicaciones y workloads. La cadena de decisión es descubrimiento → ficha → evidencia → candidate → selector → runtime → benchmark → evidence → grader/router.

Regla: una cifra publicada por un proyecto externo sigue siendo reported hasta que LEONES la reproduce con hardware, modelo, cuantización, versión y workload fijados.

Fichas

🐰 Rabbit

Runtime de investigación / disk-resident MoE. Rust; streaming de expertos desde disco, cache y persistencia de uso. Está pensado para modelos que no caben en la memoria aceleradora convencional.

Para LEONES

Candidato disk-resident-moe. Medir I/O, cache hit/miss, RAM, latencia y tokens/s. No compararlo sólo por tok/s con runtimes convencionales.

Repositorio

🍋 Lemonade

Servidor + SDK local. Expone APIs OpenAI/Anthropic/Ollama y gestiona modelos y backends, incluyendo llama.cpp y aceleración CPU/Vulkan/ROCm según configuración.

Para LEONES

Candidato runtime-adapter. Debe registrarse el backend efectivo para que una medición sea trazable.

Repositorio

🦙 llama.cpp

Baseline portable. C/C++, GGUF, cuantizaciones, CPU, Metal, CUDA, HIP, Vulkan, SYCL y CPU+GPU híbrido; incluye servidor con API compatible.

Para LEONES

Baseline canónico para hardware heterogéneo. Fijar versión, backend, quant, offload, threads, contexto y batch.

Repositorio

🧩 ODS

Stack/appliance local. Integra inferencia, Open WebUI, dashboard, voz, agentes, workflows, RAG, búsqueda, imagen y operaciones en una instalación automatizada.

Para LEONES

Capa de despliegue posterior a la selección. Debe consumir un manifiesto reproducible de hardware/modelo/runtime.

Repositorio

🦙 Ollama

Runtime/packaging de conveniencia. Facilita descargar, gestionar y usar modelos localmente y ofrece APIs para integración.

Para LEONES

Baseline de facilidad y compatibilidad. No sustituye la medición del engine efectivo.

Web

🐺 KoboldCpp

Distribución/UI sobre llama.cpp. GGUF/GGML, UI, APIs y herramientas para historias, memoria y multimodalidad.

Para LEONES

Baseline UX/GGUF y workload conversacional. Registrar las diferencias respecto al backend llama.cpp.

Repositorio

🍎 MLX-LM

Runtime Apple Silicon. Generación, fine-tuning, cuantización y Hugging Face sobre MLX y memoria unificada.

Para LEONES

Runtime prioritario en Apple. Medir memoria unificada, wired memory, TTFT, TPOT, batch y contexto.

Repositorio

⚡ vLLM · ROCm

Serving de alto rendimiento. Continuous batching, KV cache eficiente, paralelismo y APIs estándar; relevante para AMD/ROCm.

Para LEONES

Candidato prioritario para servidores AMD y cargas concurrentes. Medir throughput agregado y p50/p95/p99.

Repositorio

🦊 Fox

Servidor local de Ferrumox. Orientado a serving local y compatible con APIs Ollama/OpenAI; complementa a Rabbit.

Para LEONES

Candidato para comparar scheduling, chunked prefill, contexto y concurrencia frente a llama-server.

Fuente

🐦 Colibrì

Engine de referencia. Rabbit describe Colibrì como implementación C de referencia para GLM-5.2 y fuente de algoritmos/kernels.

Para LEONES

Referencia algorítmica para inferencia MoE extrema; no promocionarlo a runtime recomendado sin revisar estado y licencia.

Fuente primaria indirecta

GPT4All

Aplicación/ecosistema local. Interesa por UX, distribución y acceso sencillo a modelos locales.

Para LEONES

Referencia de aplicación y compatibilidad, más que baseline de microbenchmark. El enlace aportado originalmente se corrige al repositorio oficial.

Repositorio oficial

ExLlamaV2

Engine CUDA cuantizado. Especializado en inferencia local de modelos cuantizados sobre NVIDIA.

Para LEONES

Baseline de GPU NVIDIA de consumo. Comparar con llama.cpp/vLLM usando exactamente el mismo modelo, quant y workload.

Repositorio

llamafile

Distribución portable. Busca empaquetar modelo y runtime como un artefacto ejecutable fácil de transportar.

Para LEONES

Interesa para offline/edge y reproducibilidad operacional. Medir arranque, tamaño, soporte hardware y rendimiento del backend.

Repositorio

LocalAI

Gateway multi-backend. API compatible con OpenAI y capa para distintos motores/modalidades locales.

Para LEONES

Adaptador de integración. Registrar siempre el backend real para no confundir compatibilidad de API con rendimiento.

Repositorio

Jan

Aplicación local de escritorio. Convierte el uso de modelos locales en una experiencia de usuario accesible.

Para LEONES

Referencia de UX/integración. No es el baseline técnico del selector.

Repositorio

AutoGPTQ

Cuantización/engine histórico GPTQ. Importante para entender el ecosistema de cuantización, pero requiere revisar actividad y compatibilidad actual.

Para LEONES

Estado condicionado. La URL alternativa aportada originalmente apunta a otro proyecto (`llm-compressor`) y no debe sustituir la fuente primaria.

Repositorio indicado

AnythingLLM

Plataforma RAG/agentes. Documentos, embeddings, generación, agentes y múltiples proveedores; puede desplegarse localmente.

Para LEONES

Workload/harness de aplicación para comprobar recomendaciones en RAG y documentos, no engine de inferencia puro.

Repositorio

Aphrodite Engine

Engine/serving experimental. Amplía el espacio de engines para modelos y cuantizaciones que pueden tener necesidades específicas.

Para LEONES

Candidato experimental sujeto a quality gate de actividad, hardware, modelos soportados y benchmark reproducible.

Repositorio

Tabby

Servidor de coding assistant. Autoalojado y conectado a IDEs para completado y chat.

Para LEONES

Workload especializado de coding: medir TTFT, latencia de sugerencia, contexto y concurrencia.

Repositorio

text-generation-webui

UI/laboratorio local. Entorno de exploración de modelos, backends y configuraciones.

Para LEONES

Útil como laboratorio/harness; las mediciones finales deben identificar el backend real y fijar toda la configuración.

Repositorio

MSA · #sc-local

Fuente de prospección aportada. La URL `msa.millaguie.net/#sc-local` no pudo ser recuperada por el acceso web disponible en esta revisión.

Para LEONES

Se conserva como unresolved. No se inventa su contenido. Cuando pueda inspeccionarse, se añadirá una ficha primaria con autoría, alcance, fecha y taxonomía.
