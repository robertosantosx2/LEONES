Esta página describe la arquitectura operativa. La numeración de sus secciones no corresponde a la numeración de los nueve pilares oficiales. En la arquitectura canónica, Leones Prospector es la Capa 1: descubre diariamente el ecosistema y alimenta el conocimiento que posteriormente puede pasar a Leones Atlas.

Flujo conceptual: Prospector descubre → Atlas conoce → Task Intelligence entiende → Router decide → Quant/Fine-Tuning/Agents preparan → Runtime ejecuta → Benchmark & Evaluation mide.

LEONES no es solamente un benchmark de modelos: estudia la combinación de hardware, sistema operativo, backend, modelo, harness, conocimiento y herramientas que permite completar objetivos agentic localmente.

   ↓

Cada capa es sustituible. LEONES debe poder identificar cuál es el cuello de botella y recomendar el cambio con mayor impacto, en lugar de recomendar cambiar el modelo por defecto.

3. Buddy: conocimiento controlado

Objetivo
   ↓
Buddy ──► conocimiento + contexto + memoria controlada
   ↓
Harness / agente
   ↓
Modelo / backend
   ↓
Resultado
Principio: separar lo que el sistema sabe de la pieza que genera los tokens. Si mañana cambia la CPU, la GPU, el modelo, el backend o el harness, el conocimiento puede permanecer.

4. LOTB · evaluación agentiva

Las pruebas LOTB simplifican la evaluación de un sistema agentivo local. No miden solamente velocidad de generación.

PruebaQué interesa observarResultado
B01Memoria / localidad / contextoéxito + tiempo
B02Trabajo con archivos y herramientaséxito + tiempo
B03Tarea multietapaéxito/error + tiempo
B04Recuperación / conocimientoéxito/error + tiempo
B05Coding / ejecución localéxito/error + tiempo
reported → reproducible → verified
                    ↘ rejected

Publicar un resultado no lo convierte automáticamente en verificado.

Regla: no optimizar tok/s aisladamente. La recomendación debe buscar la mejora de la experiencia real al completar tareas.

6. Reingeniería: scripts pequeños

Los scripts deben hacer pocas cosas, muy claras y bien documentadas. Un script puede llamar a otros, pero no debe convertirse en un orquestador monolítico.

01

hardware

Extrae las características técnicas básicas de la máquina.

02

model

Identifica y documenta el modelo y su configuración.

03

infer

Ejecuta mediciones de inferencia contra el backend.

04

lotb

Ejecuta las pruebas agentivas estandarizadas.

05

report

Convierte los resultados en el formato público.

06

publish / stats

Publica informes y genera estadísticas para la web.

hardware → model → infer → LOTB → report → publish → stats

7. Instalación y ejecución

Ubuntu

git clone https://github.com/robertosantosx2/LEONES.git
cd LEONES
python3 --version
python3 scripts/leones.py hardware

La pila debe documentar drivers, runtime, backend, modelo, harness y LOTB. Las piezas concretas pueden cambiar según CPU/GPU.

Red Hat / RHEL

git clone https://github.com/robertosantosx2/LEONES.git
cd LEONES
python3 --version
python3 scripts/leones.py hardware

La misma arquitectura se conserva; cambian paquetes del sistema, gestión de drivers y detalles del runtime.

Flujo de una ejecución

1. detectar hardware
2. seleccionar/configurar modelo
3. levantar backend
4. ejecutar inferencia
5. ejecutar LOTB
6. generar result.json + report.md
7. publicar opcionalmente
8. actualizar estadísticas

Regla fijada: LEONES descubre las piezas Open según OSI, pero prioriza las Copyleft. Descubrimiento no equivale a recomendación.

Prospección semanal

Además de la búsqueda diaria de piezas, cada semana se investigan proyectos que puedan mejorar las skills, funciones o características de los harnesses. Los candidatos compatibles aparecen en un menú de recomendaciones para que el usuario decida si instalarlos.

10. manada_leones

El usuario puede aportar resultados de su máquina. El objetivo es construir evidencia distribuida sobre hardware real y mejorar las recomendaciones futuras.

USUARIO → result.json → validación → manada_leones
                                      ↓
                                    Atlas
                                      ↓
                                    Router

11. Automatización

La automatización debe coordinar piezas pequeñas y mantener trazabilidad. El sistema puede ejecutar prospección, pruebas, generación de informes y publicación, pero cada resultado debe conservar su origen y estado de validación.
