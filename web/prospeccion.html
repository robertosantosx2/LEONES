La prospección es diaria. LEONES busca modelos, proyectos, software, runtimes, agentes, herramientas, benchmarks, técnicas de eficiencia y componentes relacionados con hardware.

La licencia es el primer criterio

Solo entran en el conjunto principal de hallazgos los candidatos cuya licencia SPDX declarada por GitHub corresponde a una licencia aprobada por la Open Source Initiative (OSI).

El bot consulta el catálogo actual de licencias aprobadas por OSI y utiliza ese universo como puerta de entrada. Después se evalúan relevancia técnica, actividad, arquitectura, reproducibilidad, hardware y utilidad para LEONES.

Copyleft prioritario

Dentro de todo el universo OSI, LEONES destaca estas cinco licencias:

GPL-2.0 · GPL-3.0 · AGPL-3.0 · LGPL-2.1 · LGPL-3.0

Los hallazgos con una de ellas aparecen con fondo verde. El verde indica prioridad de licencia, no aprobación técnica.

Regla de evidencia

Un hallazgo de Prospector no se convierte automáticamente en conocimiento de Atlas. Primero debe existir revisión y evidencia suficiente.

OSI aprobado no significa recomendado. La licencia es el primer filtro. Después vienen la relevancia técnica, la actividad, la arquitectura, los requisitos de hardware, la reproducibilidad y la compatibilidad con la pila LEONES.

Cómo se incorporan

Descubrimiento → OSI → revisión → evidencia → Atlas → Router.

Los candidatos sin licencia OSI aprobada o sin licencia identificable no se presentan como hallazgos OSI aprobados.
