RUNTIME

Ejecución separada

La recomendación no autoriza ejecución automáticamente. El usuario elige y confirma; después el runtime ejecuta y el benchmark produce evidencia.

RC4 · contrato

Instalación permanente de software IA

Regla normativa para todo software IA que LEONES gestione, incluidos los componentes futuros:

1. instalación desde cero
2. detección de instalación rota → reparación
3. detección de versión actual → no actualizar innecesariamente
4. versión antigua → actualización real
5. verificación operacional posterior
El contrato es común para FitLLM, ODS, Magnitude, Hermes y OpenHands Manager, y debe mantenerse también en cualquier componente IA futuro.

Prospector descubre. Atlas conserva conocimiento. Task Intelligence interpreta la necesidad. Router decide. Quant y Fine-Tuning adaptan. Agents actúa. Runtime ejecuta. Benchmark & Evaluation mide y devuelve evidencia.

ACTIVO · diarioPILAR 1

Prospector

Descubre qué está cambiando. Modelos, runtimes, harnesses, skills, cuantizaciones, eficiencia, hardware y benchmarks.

ACTIVO · en evoluciónPILAR 2

Atlas

Conserva conocimiento estructurado y procedencia. Modelos, familias, organizaciones, licencias, formatos, hardware, runtimes, benchmarks y evidencia.

RC4 · operativo en el flujoPILAR 3

Task Intelligence

Entiende qué se quiere conseguir. RC4 pide la intención antes de recomendar y permite seleccionar programming, reasoning, research, chat, multimodal, embedding y general.

RC4 · recomendaciónPILAR 4

Router

Decide qué pila encaja. Combina propósito, hardware, modelos candidatos, cuantización, backend y evidencia disponible.

INICIALPILAR 5

Quant

Adapta la representación del modelo. Equilibra calidad, memoria y velocidad manteniendo trazabilidad.

INICIALPILAR 6

Fine-Tuning

Adapta modelos cuando hace falta. Incluye PEFT, LoRA y QLoRA cuando la evidencia justifica la adaptación.

INICIALPILAR 7

Agents

Convierte el modelo en capacidad de acción. Planificación, herramientas, memoria, RAG, workflows y recuperación ante errores.

RC4 · backend independientePILAR 8

Runtime

Ejecuta localmente. Abstrae motores como llama.cpp, Ollama, Transformers, vLLM, MLX y otros según hardware y objetivo.

ACTIVO · evidencia realPILAR 9

Benchmark & Evaluation

Mide y produce evidencia. Registra inferencia, memoria, latencia, estabilidad y resultados reproducibles que pueden volver a Atlas y mejorar Router.

Bucle de aprendizaje

La cadena completa

SELECCIÓN DECLARATIVA → RUNTIME → EJECUCIÓN → MEDICIÓN → EVIDENCIA → RECOMENDACIÓN
         ↑                                                                          ↓
         └─────────────────────────────── APRENDIZAJE ─────────────────────────────┘

La arquitectura separa claramente lo que el sistema estima de lo que realmente mide. La evidencia física no se fabrica ni se sustituye por una predicción.

Cómo debe usarlo una persona

1 · Idioma

Selecciona el idioma. A partir de ahí, la TUI mantiene navegación y estado visibles.

2 · Intención

Marca uno o varios usos. La selección es declarativa y precede a la recomendación.

3 · Recomendación

Revisa propuestas ESTIMATED y elige. No existe ejecución automática.

4 · Ejecución

Confirma la acción. El runtime ejecuta, mide y registra evidencia real.
