Estado del sistema

Cargando estado canónico…

La aplicación lee web/data/stats.json y mantiene las operaciones locales del navegador separadas de los datos publicados.

Arquitectura operativa

PROSPECTOR → ATLAS → TASK INTELLIGENCE → ROUTER
                       ↓
             QUANT / FINE-TUNING / AGENTS
                       ↓
                    RUNTIME
                       ↓
             BENCHMARK & EVALUATION
                       ↓
                   EVIDENCIA

Principio de decisión

La aplicación no elige por “modelo más grande”. Primero interpreta la tarea, después comprueba restricciones de hardware y finalmente propone modelo + cuantización + backend, indicando cuando la evidencia es insuficiente.

Leones Router

Primera versión transparente. No pretende sustituir benchmarks reales: convierte restricciones conocidas en una recomendación explicable.

Reglas visibles

CPU / poca memoriaPriorizar modelos pequeños GGUF y llama.cpp.
GPU NVIDIAConsiderar CUDA; ExLlama/vLLM según uso y concurrencia.
AgenteLa velocidad de un modelo no basta: importan herramientas, recuperación y evaluación LOTB.
Contexto largoLa caché KV y la memoria disponible pasan a ser restricciones explícitas.

Leones Atlas · memoria estructurada

Esta vista muestra el conocimiento local introducido en la aplicación. En esta primera versión se puede importar un catálogo JSON; los datos publicados del proyecto siguen siendo la fuente canónica para resultados oficiales.

Prospector · cola local

Los hallazgos se guardan en el navegador hasta que un proceso de revisión los convierta en evidencia de Atlas.

Cola de revisión

LOTB · panel de evaluación

La aplicación registra localmente resultados de prueba. Para que un resultado sea oficial debe seguir el esquema y política de evidencia del repositorio.

Datos y portabilidad

Exporta o importa el estado local para mover la aplicación entre navegadores. No se envía automáticamente a ningún servidor.
