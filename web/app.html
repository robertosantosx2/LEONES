Decide

Router · recomendación provisional

La recomendación debe evolucionar desde reglas iniciales hacia evidencia de Atlas.

Qué debe decidir Router

Hardware → memoria disponible → tarea → modelo candidato → runtime → evidencia existente.

No es una sentencia definitiva. Si Atlas contiene evidencia suficiente para tu combinación de hardware/modelo/runtime, esa evidencia debe sustituir a la heurística.
Conoce

Atlas + Prospección

El conocimiento no se inventa en Router: se descubre, se revisa y se conserva.

Prospección diaria

Busca modelos, runtimes, harnesses, skills, cuantizaciones, proyectos de eficiencia, benchmarks y cambios que puedan alterar las recomendaciones.

Prospector → externo no validado → revisión → Atlas

Por qué es diaria

El ecosistema cambia demasiado rápido para que una recomendación estática siga siendo fiable. La prospección detecta cambios; la revisión decide si son relevantes.

Principio: LOTB aporta evidencia sobre una combinación de modelo + runtime + herramientas. No debe confundirse con una puntuación abstracta del modelo.
Comparte

Manada LEONES

Compartir es voluntario. El beneficio es colectivo: más evidencia real permite mejores recomendaciones.

Flujo recomendado

MEDIR → INFORME → PRIVACIDAD → REVISAR → COMPARTIR → AGREGAR → APRENDER

Qué nunca debería salir

Nombres, usuarios, rutas personales, seriales, UUID, MAC/IP, credenciales, tokens, archivos personales o cualquier dato que identifique tu máquina o tu persona.

Control humano: LEONES prepara la evidencia; tú decides qué compartir. La web no publica automáticamente en tus cuentas.
